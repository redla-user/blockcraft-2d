# Browser Craft

We are going to build 2d birds eye view minecraft which works on any browser yeah even on chrome 109 too. Starting with home screen with buttons play and then u can create world and select the word type means easy or hard and create and play and survive. 1. Controls

The core rule: game logic never checks a physical key directly — it only checks a logical action like "move up" or "mine or place." A separate small mapping layer translates each device's physical buttons into these actions. This is what lets the exact same game code run on a TV remote (which has arrows, Enter, volume, numbers) and a laptop keyboard (which has everything) without writing the game twice.

Move — arrow keys on both TV and laptop. Confirmed to work on webOS.

Mine/Place — one button (Enter/OK). It's context-sensitive: if you're facing a breakable block, it mines; if you're facing empty walkable ground, it places whatever's in your selected hotbar slot. One button instead of two keeps it simple for a younger/first-time player.

Jump/Sneak — deferred entirely for now. No mechanic currently needs them, so they're not being built.

Hotbar select — number keys 1–9, picks which hotbar slot is active.

Open/close inventory — pressing 0 toggles the full inventory screen open or closed.

Pause — Back button on the TV remote (which has a special reserved code, so we don't fight it) / Escape on laptop.

2. World data

The world is a flat grid of tiles — no elevation, no height, just rows and columns. Each tile stores three things: its type (dirt, grass, water, stone, iron ore, diamond ore), whether it's walkable, and whether there's an object sitting on it (a tree, a placed block, etc.).

Ore tiles aren't a separate category from stone — they're just a stone tile with an ore graphic drawn on top. That way mining logic, collision, and rendering are all shared with plain stone; only the result of mining differs.

The world is broken into chunks — fixed-size squares of tiles (say 16×16). Each chunk's contents are generated by a formula that takes the world's seed plus that chunk's coordinates and deterministically produces the same tiles every time. This matters a lot for saving later: since a chunk can always be regenerated from the seed, we never have to store the whole thing — only what's changed.

3. Rendering vs. collision — two separate systems

This is the trick that makes trees and mountains look like they have height in a flat game, and it's important these two systems stay separate:

Collision answers "can the player walk here?" — a plain true/false per tile. Trees, mountains, stone, and placed blocks mark their base tile as blocked. That's it — no climbing, no partial heights.

Drawing order answers "what's on top visually?" — completely independent of collision. Ground tiles (dirt, water, stone) get drawn first in one simple pass, no sorting needed. Then every "tall" thing — the player, mobs, trees, mountains — gets drawn in a second pass, sorted by the Y-position of its base (the bottom of its sprite, where it touches the ground) rather than its center. Whichever entity has a lower base-Y on screen gets drawn first (further back); higher base-Y draws after (closer to camera, on top).

The payoff: if the player is above a tree on screen, the tree draws over the player's legs and it looks like the player is standing behind it. If the player is below the tree, the player draws over the tree's trunk and it looks like standing in front. One sorting rule produces this effect for every tall object automatically — mountains use the identical trick, just with a bigger sprite and a wider blocked footprint.

4. Mobs

Passive mobs — pig, cow, sheep — wander randomly and flee briefly when hit. Pigs and cows drop meat for food; sheep drop wool, used for crafting beds.

Night mobs — zombie, skeleton, spider, creeper — only appear once it's dark. Zombies walk straight toward the player when in range. Skeletons keep their distance and fire projectiles. Spiders move faster and more erratically than zombies. Creepers are the most complex: they quietly approach, then enter a fuse/flashing state, then explode.

All five active mobs are built from one shared AI class — wander or chase, with parameters like speed, detection range, and attack type varying per mob — rather than five separate systems. The creeper's extra explode logic sits on top of that shared base and is saved for last since it's the trickiest piece.

5. Day/night cycle

A single clock value ticks through a full day. During the day, passive mobs may appear and night mobs stay dormant or despawn. As it gets dark, night mobs begin spawning near the edges of what's visible. Sleeping in a bed at night fades the screen to black for a short pause, then resumes at the start of the next day — skipping the rest of the night entirely.

6. Tools & tiers

Each tool is just a small data record — {type, tier} — rather than a unique class per tool. Types are sword, pickaxe, hoe, and axe; tiers run wood → stone → iron → diamond, where each tier unlocks mining/using materials the previous tier couldn't reach (e.g. only a stone-or-better pickaxe can mine iron).

Pickaxe mines stone, iron, and diamond — higher tiers mine faster and unlock the next material.

Axe chops trees faster at higher tiers.

Hoe tills dirt into farmland, feeding into the food/crop system.

Sword deals more damage per hit at higher tiers.

There's no smelting yet — iron and diamond tools are crafted straight from the raw ore you mine. This is a deliberate simplification, and it leaves a clean gap to slot in a furnace/smelting step later without touching anything else about how tools work. There's also no armor in this version.

7. Crafting

There's no crafting-table object to build or place, and no manual recipe grid to arrange pieces in — crafting lives entirely inside the inventory menu. Recipes are stored as simple data: a result item plus the ingredients and quantities it needs, tagged with a category (tools, food, beds, etc.). When you open the crafting menu, it shows these recipes grouped by category as "these materials → this result" cards. If you're currently holding enough materials, a CRAFT button appears automatically on that recipe; if not, it's still shown but can't be used. Clicking CRAFT deducts the ingredients and adds the result to your inventory — no assembly required.

8. Inventory

The hotbar takes up slots 1–9 and stays visible during normal play. Pressing 0 opens the full inventory as an overlay (which pauses movement); pressing 0 again closes it and returns to the game. Inside the overlay: clicking an item picks it up onto your cursor, clicking another slot places or swaps it there, clicking anywhere outside the inventory box drops the held item into the world, and clicking an already-occupied slot while holding something swaps the two.

Eating works the same interaction style: click a food item, then click any tile or block, and the character automatically eats it and restores hunger.

9. Health & hunger

These are two separate bars, not merged. Health drops from mob damage, and also drains slowly if hunger hits zero — so starving eventually becomes dangerous even without a mob nearby. Hunger drains gradually over time and gets refilled by eating meat (from pigs/cows) or crops grown on hoe-tilled farmland.

10. Saving — local storage

Only two things get saved to the browser's local storage: the player's inventory, and chunk/biome changes.

Inventory is one small data blob: hotbar, full inventory, health, hunger, and player position.

Chunks are never stored in full. Since any chunk can be regenerated exactly from the world seed plus its coordinates, we only need to remember what changed. A chunk only gets a storage entry once the player actually breaks, places, or mines something in it — and what's stored is just a short list of those individual tile changes, not the whole chunk grid. When a chunk loads, it's regenerated fresh from the seed, and then those saved changes are reapplied on top. A chunk the player never touched has no entry at all — it just regenerates the same way every time.

11. Build order

Smallest, safest slice first, hardest piece last:

A quick remote-key test page on the actual TV, to confirm which physical buttons really reach the browser before writing any game logic against them.

A single static biome with movement and rendering only — proves the game runs well on the real TV.

Mining with the tool-tier gate.

Building/placing from the hotbar.

Day/night cycle plus night mobs.

Infinite biome generation — the most complex piece, deliberately saved for last once everything else is proven. soemthing like attachement but recognisable!
